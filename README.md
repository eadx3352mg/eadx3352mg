## 🛠️ 工具与产品实践

这些工具主要来自实际工作或生活中遇到的具体问题。我尝试把其中重复、低效或者适合标准化的工作，通过软件和 AI 工具转化为可以真正使用的产品。

### 🧠 知识工程工作台（KEW）

面向专业资料处理、知识沉淀和 AI 知识应用的本地知识工程工具。

用于将方案、标书、技术资料等非结构化文档进行清洗、切分（Chunk）、标签化和向量化处理，为后续知识检索、RAG 和 Agent 应用准备可复用的知识资产。

**基本处理链路：**

`原始资料 → 清洗 → 切分 → 标签 → 向量化 → 知识资产 → RAG / Agent`

> 项目仓库链接待整理后补充。

### 🔎 [BidRadar / 标讯雷达](https://github.com/eadx3352mg/BidRadar)

面向招投标工作的多源公共标讯聚合与筛选工具，海投提效关键利器。

针对公开招投标信息分散在不同政府采购和公共资源交易平台的问题，对近期机会类公告进行统一采集、关键词匹配、详情解析、跨源去重和历史去重，并输出结构化 Excel。

**主要处理链路：**

`多源采集 → 机会公告过滤 → 多关键词匹配 → 详情解析 → 去重 → Excel`

**技术实现：** `Python` · `SQLite` · `Windows GUI` · `Collector Architecture`

> 项目仓库：[BidRadar](https://github.com/eadx3352mg/BidRadar)。

### 🎞️ [SnapGIF](https://github.com/eadx3352mg/SnapGIF)

一个轻量级 Windows 视频处理工具，用于从长视频中周期性提取短片段并生成 GIF。

> 项目仓库：[SnapGIF](https://github.com/eadx3352mg/SnapGIF)。

## 💬 写在最后

这里的很多东西都谈不上多么宏大叙事，而更多是聚沙成塔的实践积累。它们来自我这些年的项目实践，市场需求，行业观察和个人思考。

标讯雷达的开发最初只是因为需要每天到不同网站找标讯来支撑自己的 KPI；而知识工程工作台的出现，是因为手里的方案和资料越来越多，需要一个适合我的工具来进行归集和治理；而写《数据资产管理与解决方案实战》则完全是想能让自己碎片化、来源繁杂的数据知识好好梳理一遍，逐渐形成体系，也希望借此能让自己对数据的理解有所提升。

这些改变我也想把它们记录下来。

所以这个 GitHub 也算是我的一个长期实验场。
